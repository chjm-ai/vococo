# 派发统一：实现与测试方案

状态：主人已批准实施；M0～M5 代码、浏览器验收与独立评审已完成，正在合并收尾；生产开关默认关闭。
日期：2026-11-09

## 1. 已确认目标

给模型只暴露两个派发工具，不用 mode 参数将两种意图重新混在一个工具里：

| 工具 | 意图 | 展示 | 完成行为 |
|---|---|---|---|
| dispatch_task | 为当前任务分工 | 当前会话任务树，默认不进侧栏 | 回传并驱动父任务继续 |
| dispatch_session | 独立推进另一个主题 | 独立会话、侧栏；来源保留入口 | 通知，不自动续跑来源 |

两者均持久保存会话，支持进入查看和人工续聊。Agent、模型、目录是选项，不再成为独立派发工具。run_subagent、delegate_to_agent 的模型可见入口退休；Claude 原生 Agent/Task 禁用。保留干净上下文的独立代码评审能力，迁移到 dispatch_task 内部受控评审执行配置。

本次包含：统一任务关系、权限及模型解析、进度/结果、自动续跑、任务树、渠道接入、旧数据兼容。首版使用可折叠树形视图，不做自由拖拽缩放脑图、不改研究引擎、不扩展外部 MCP 协议。后续可在同一关系数据上补脑图。

## 2. 现状与必须保留的约束

- core/subagent.py：当前同步等待、无会话持久化、最多一层、限制工具与能力、计入父轮用量。
- core/delegation.py：已有来源/祖先链、两层五任务限制、按 run_version 回执去重；回执写入外部上下文和未读，不自动启动父轮。
- core/task_runner.py：共享队列、运行预算、终态收尾、模型会话恢复、任务 worktree；普通 dispatch 仅在自动链存在时进入委托账本。
- core/session_execution.py：前台和任务共享轮次、事件流、会话恢复。
- core/task_events.py / core/completion.py：已有进度事件及统一完成通知；不得再造一套系统通知。
- tools/sessions.py：跨会话忙碌检查、自动来源与真人来源区分，不得用伪造用户输入唤醒父任务。
- voice/task_tools.py：续接候选检测、语音来源与通知目标；voice/notify.py 仅语音来源播报。
- gateway/brain_routes.py / mcp_events.py：外部 MCP 独立身份、幂等、防二次派发、连接隔离、终态 webhook。
- 工作台保留任务与会话关联；定时保留 job/session/run 区分、独立自动上下文、脚本静默、统计和附加目标；历史研究保持只读查询、清理与拒绝重新执行，不恢复已移除的研究执行器。

来源渠道、任务关系、执行者必须分开，不再靠 origin 或会话前缀猜父子关系。

## 3. 数据设计

优先复用 tasks、会话存储、现有来源账本，不新建第二套任务执行表。实施前定向测试旧表迁移。

### 3.1 任务元数据

- relation：child / independent；旧普通任务默认保持独立，不因 source_session_key 存在而变为 child。
- parent_session_key、parent_execution_id：绑定明确的父会话和本次主任务执行，而不是永远挂在同一个聊天上。
- parent_task_id、root_execution_id：嵌套与汇总；父会话可能没有后台 task_id，不能要求父节点一定存在于 tasks。
- origin、dispatch_platform、dispatch_chat_id：保留来源渠道与通知目标。
- agent_id、chosen_model、cwd：复用现有归属、模型、目录字段。
- source_access：服务端捕获权限与能力快照，不允许模型填写。

### 3.2 回传与续跑账本

复用/扩展 delegation 关系和回执账本；唯一处理键为 child_task_id + child_run_version + parent_execution_id。分开记录：

1. 子执行已终态。
2. 结果已写入父任务可读上下文。
3. 自动续跑已领取。
4. 父轮成功处理了哪些结果。

写入回执不等于已处理。父轮失败不提前确认处理，重试读取同一批回执，不重复追加正文。

父任务协调状态单独持久化：active / waiting_children / cancelled / completed；不要把有子任务的模型单轮正常结束误判为整个主任务完成。保留自动续跑代数、根任务用量及最后一次真人输入版本。

### 3.3 历史兼容

- 只做增量结构迁移，不批量重写生产会话 ID、历史、归属或目录。
- 旧普通派发维持侧栏、通知与续接行为；旧委托仍可读取账本及历史回执。
- 旧链不因升级产生新的自动续跑。新建 child 才启用新协调机制。
- 结构迁移重复执行安全；历史链关系缺失时不猜父任务、不自动恢复权限。

## 4. 工具与执行服务

### 4.1 两个新入口

dispatch_task / dispatch_session 共用 title、prompt、可选 agent/model/cwd。child 必须能确认父执行；否则明确拒绝，不能静默降级独立任务。非法/重名 Agent、模型匹配歧义、目录错误均在起跑前拒绝。

工具立即返回 task_id、session_id、状态与链接信息；等待和续跑由服务端协调，不增加第三个模型可见的“等待工具”。

- dispatch_task：父代理可以继续做其他工作。当前轮次结束但仍有 child 时进入协调等待；所有本轮尚未消费的直接子任务达到终态后，合并一批回执自动续跑。首版不做逐个子结果到达即重启，降低竞争和成本。
- dispatch_session：独立起跑，仅通知，不注册自动续跑关系。

未显式设置模型时：网页继承当前模型；语音保留语音任务执行侧默认，不继承实时音频模型；MCP 保留执行侧配置；定时以规则设置为准。先测试冻结当前实际行为，再实施这些明确的默认值，不依据可能过时的工具说明猜模型。

### 4.2 权限与能力

共用现有权限/审批/业务执行策略，不新增权限档位。来源禁用项与目标禁用项叠加，来源可用技能/MCP 能力不能因为换 Agent 或改模型自动扩大。未能证明的能力默认不授予。

外部 MCP 保持禁止二次派发；旧禁用 run_subagent/delegate_to_agent/Agent/Task 的配置需映射到新 child 入口，禁用旧 dispatch_session 继续禁止独立派发。映射采用收紧原则，不自动清空限制；单测覆盖前缀和通配符。

不把子结果当真人命令，不允许工具参数覆盖来源、权限、父节点、通知连接、幂等身份。

### 4.3 目录与评审例外

普通可写任务延续独立 worktree，失败不退回主检出目录。保存执行目录并确保续聊回到原目录。

代码评审使用服务端只读执行配置：干净模型上下文、读取父 worktree 的未提交改动与本分支 diff，不另开一份没有改动的 worktree；禁止修改及再次派发。现有评审 Bash 只是约定只读，实施时需明确受控命令/写操作拦截，不把 Bash 可写性当成已解决。

评审配置是受控例外，不允许普通 dispatch_task 通过传 cwd 或 prompt 获得父目录共享写权限。独立评审与 SDK Agent 禁用必须同批接通，不能出现无评审窗口。

## 5. 自动续跑、并发与取消

### 5.1 协调过程

1. 创建 child 与父执行关系后起跑或排队，展示进度。
2. 父轮仍在输出时，只累积回执，不并发往同一 SDK 会话发送 query。
3. 父轮已结束且子任务未齐：标 waiting_children，释放任务执行并发位和模型连接，不用长驻 SDK 等待。
4. 子任务成功/失败/取消都算终态。全部直接子任务达到终态后，事务领取本批续跑，送入现有执行队列。
5. 自动轮次以专用自动来源携带权限和结果引用，复用会话恢复与外部回执注入，不伪装真人发言；成功后确认消费的精确结果版本。
6. 已无未完成子任务且未再派发时，父任务可结束。嵌套子任务未处理完，不向更上级提前宣告整项成功。

父任务等待不得占满 TASK_MAX_CONCURRENCY，否则父任务占满并发、子任务排队会死锁。测试并发上限为 1 的场景。续跑按普通队列调度，不绕过并发限制；等待不消耗模型 token，不高频轮询模型。

### 5.2 新输入、阻塞和版本

- 父会话忙碌、审批/澄清待答：延后续跑，不替用户确认。阻塞有明确可见状态和解决入口。
- 真人新输入先改变父执行版本，旧续跑领取失效；回执仍可见，新轮次决定是否使用，不自动执行旧方案。
- 人工进入 child 查看不改变归属；人工追问的新轮次默认展示但不重新唤醒已结束的父执行。主代理明确补做时才登记新的待处理 child 版本。
- 父会话删除/主任务取消/已完成：停止自动唤醒，保留已有结果，不复活父会话。
- 浏览器关闭不等于取消；显式“停止整个任务”取消本执行的自动续跑与未完成后代，不触碰独立会话。单个子任务停止不取消兄弟节点，失败/取消交给父代理处理。
- 服务重启：恢复待回传/待续跑账本；未确认提交的续跑允许恢复领取，必须用持久化轮次关联避免重复开始。工具外部副作用不承诺恰好一次，继续沿用审批和业务幂等。

### 5.3 链路和费用上限

首版保留当前自动链最多两层、同链五任务的保护，不通过另开会话入口重置自动链。达到限制明确报告。

用量按实际执行记录一次，再聚合到根任务，不能既算 child 又重复算 root。设置自动续跑次数上限并受现有每日预算约束；异常反复派活达到限制后停在“需要处理”，不无限唤醒。具体新增上限放配置，实施时给出默认值与边界测试，不静默取消预算限制。

## 6. 渠道接入与通知

| 入口 | 实施处理 | 不能回归的行为 |
|---|---|---|
| 网页聊天 | 两个 MCP 工具映射统一服务；更新 prompt、工具挂载、危险提示与旧别名策略 | 工具禁用、任务进度、会话恢复、审批 |
| 语音 | 同一两种语义，保留协议适配层；同一模型上下文不同时挂新旧重名语义工具 | 候选续接、模型默认、通话播报、挂断后结果可查 |
| 外部 MCP create_task | 保持现有外部名称/参数/幂等注册；内部接独立执行路径，不伪造本地父会话 | 固定执行者、连接归属、终态 webhook、查询及继续历史会话 |
| 工作台执行按钮 | 独立会话路径，保留 link_session | 任务备注、项目目录匹配、任务卡片入口 |
| 定时 AI | 保留调度入口，经共用执行服务，不绑定当前聊天父任务 | 模型权威、自动 fresh、人工 resume、统计/附加推送 |
| 定时脚本 | 不经过模型派发工具，不改脚本执行路径 | 零 LLM、静默标记、停止与失败策略 |
| 历史研究 | 保留历史只读兼容，不恢复已移除的执行器 | 历史可查、拒绝新建/续跑、恢复时清理旧在途状态 |
| 真人续聊 | 沿用现有统一会话执行链路 | 不继承过期自动触发/定时策略，不重复创建任务 |

外部 MCP 不承诺强制唤醒外部客户端；保留完成 webhook + 主动查询，逐步进度仅内部页面展示，协议新增留待后续。语音实时会话不能直接当文字 SDK 会话 resume：活跃通话通过其现有事件/播报适配器回传，通话关闭后只持久保存/通知，不自行重建通话。第一批语音播报聚合，避免每个子节点和父汇总各播一遍。

系统完成通知继续唯一走 core/completion.py。子任务进度/结果作为状态事件，正常批次仅父最终汇总产生一次用户完成通知；独立任务各自通知。失败、阻塞、父任务无法恢复时不能被聚合策略吞掉，需明确告知和提供入口。定时/研究维持各自既有通知策略。

## 7. 前端与接口

- 基于现有会话/工具卡片与 SSE 加任务树组件，不重写聊天页面、不引入图布局依赖。
- 节点显示任务标题、执行者/模型、排队/运行/阻塞/成功/失败/取消、最后进度及结果摘要；执行状态与“已回传/已处理”分开。
- 父任务运行与 waiting_children 明确区分，不显示“已完成”后悄悄重新执行。
- 点击打开原会话，显示返回父任务入口，支持多层返回；进入、刷新、浏览器前进后退保持定位。
- child 从 Agent 列表、最近列表及侧栏其他聚合入口一致隐藏；搜索可找，结果标明父任务。独立会话保持现状。
- 关系 API 校验读取权限，不能凭一个 task_id 浏览其他来源树；进度事件携带关系和执行版本，过期事件不覆盖新轮次。
- SSE 断线后拉持久化快照恢复，不只依赖内存事件；进度节流沿用现有节奏，不将每步日志塞进父上下文。
- 桌面/手机树形列表，键盘可操作；深浅主题使用 DESIGN.md 变量。自由画布不在首版。

## 8. 分批实施与闸门

每批先跑该批定向回归再进入下一批，不用一次改完才测。阶段内尽量控制三个主要模块，前后端接入再分小批。

| 阶段 | 主要落点 | 完成条件 |
|---|---|---|
| M0 基线与数据 | tasks、delegation、关系测试 | 保存基线失败；结构迁移重复安全；旧数据/旧路由不改变 |
| M1 统一派发 | 共用服务、两个工具、权限/模型/目录解析 | 两种任务可执行、保存会话、续聊；旧入口兼容但不与新入口同时暴露 |
| M2 协调续跑 | 父执行账本、task_runner、网关自动来源接入 | 释放并发、版本化回传、领取/确认、失败和重启恢复通过 |
| M3 渠道迁移 | 语音、外部 MCP、工作台分批 | 外部契约不变；语音挂断/播报正常；定时研究无回归 |
| M4 任务树 | 关系接口、卡片/侧栏、断线恢复 | 树内可查看/续聊；侧栏不漏显；手机/桌面浏览器通过 |
| M5 退休与收尾 | SDK 屏蔽、评审迁移、prompt/文档和兼容 | 两工具唯一可见；独立评审能力保留；安全/全量回归与独立代码评审 |

阶段能力采用明确发布开关，默认旧行为，测试/本地实例启用；生产只在完整链路验收后启用，绝不出现隐藏子任务但无树入口。不要用一堆永久开关维持两套实现。旧调用仅作短期适配，记录命中，不再作为新模型工具暴露。

## 9. 测试方案

### 9.1 离线单元与集成

使用临时数据库/临时 Git 仓库和可控模型事件流，覆盖真实创建、调度、存储、续接及事件链；仅替换供应商调用、系统推送/TTS/webhook 外部副作用，不把核心调度/权限全部 mock。生产配置与真实任务不作为测试对象。

| 组 | 必测情形与断言 |
|---|---|
| 数据 | 空库/旧库/混合库；重复升级；字段缺失/关系损坏；旧 ID 可查可续接，无旧任务自动唤醒 |
| 工具 | 两个 schema 唯一可见；默认/指定 Agent/模型/目录；歧义拒绝；父执行缺失拒绝；旧原生 Agent/Task 硬拦 |
| 正常闭环 | 父派 1/多个子任务，进度持续；父完成自己的工作后等待；子齐后只续跑一次；结果全文可查、摘要注入、消费确认 |
| 嵌套 | 两层成功/失败；最底层未处理不得上报顶层完成；第三层/第六项/绕祖先/换入口绕过拒绝 |
| 并发 | 上限 1 仍能父→子→父；多父不饿死；父忙/澄清/审批阻塞；同时终态、重复终态、抢占续跑只启动一次 |
| 生命周期 | 单子取消、整树停止、独立任务不受影响；真人新输入使旧唤醒失效；查看不改变关系；人工续聊不复活旧父任务 |
| 恢复 | 在结果保存前后、领取前后、父轮启动前后、处理确认前后注入故障；重启补投不重复正文、不并发 query，不宣称失败轮已处理 |
| 权限 | 来源/目标禁用项、通配符、标准/完全权限；技能/MCP 能力不能增加；外部 MCP 禁二次派发；拒绝后不能换入口绕行 |
| 文件与评审 | 每个写任务独立 worktree；失败不退主目录；续聊原目录；评审确实看到父分支和未提交 diff、无写权限 |
| 费用 | child 用量记录一次；聚合不重复；每日/根任务预算及续跑上限；超限明确停止，等待不调用模型 |
| 语音 | 候选检测及复用任务；指定/默认模型；通话中聚合播报；挂断后保存/通知；不把实时音频模型用于后台执行 |
| MCP | 请求重放不新建；连接隔离；完成/失败/取消 webhook；续接新 run_version；忙时拒绝；历史归档会话续接及权限不变 |
| 通知 | 子正常完成不产生通知风暴；父最终一次；失败/阻塞不静默丢；独立任务一次；SSE/回执不再产生额外系统通知 |
| 旁路回归 | 工作台 link_session；定时 fresh/人工 resume/规则移转删除；脚本静默；历史研究只读及拒绝执行；所有来源停止和恢复 |

### 9.2 本地浏览器端到端

使用隔离数据根启动本地实例，通过现有浏览器测试方式注入可控后端事件，Playwright 实际点击，不连接生产：

1. 桌面父任务派多个 child：看到树及进度，独立任务仍进侧栏。
2. 点击子会话、追问、返回父任务、刷新、前进后退，历史和定位不丢。
3. 排队/等待/失败/取消/审批阻塞/父自动续跑/最终完成均有正确状态。

## 10. 合并、启用与回退

- 本方案确认前不改执行代码。实现后必须独立只读代码评审，修正确认问题，相关及全量回归合格后提交、合并；按项目规则推送并报告。
- 生产不做破坏性迁移、不清历史、不自动清旧 worktree；生产数据备份、开关启用和重启按审批执行，后端重启另询问。
- 首次启用只对新派发启用新关系；旧在途任务继续旧收尾，不能强行迁入自动续跑。
- 回退优先关闭新派发/自动续跑开关，停止领取待续跑，已执行的 child 允许收尾，保留会话/结果/账本；不撤销真实外部操作。
- 不直接将含新 child 数据的数据库交给任意旧二进制，旧代码可能把隐藏任务展示成独立任务；需用已验证的兼容版本回退，或先让新执行排空。任何恢复数据库备份前说明将丢失哪些新结果并另行确认。

## 11. 放行标准

1. 模型只看到两个派发工具，原生 Agent/Task 被硬拦，独立评审可用。
2. 新 child 不占侧栏但随时可进入、续聊、回父任务；独立任务行为不变。
3. 全链父子关系、状态、结果/已处理版本重启不丢；无并发死锁、重复唤醒、过期自动动作。
4. 自动来源、外部 MCP、预算、目录隔离与审批规则无放宽。
5. 语音、网页、MCP、工作台、定时、研究、普通续聊完成回归；未验证项明确列出。
6. 未经确认不启用生产、不重启；浏览器验收、独立代码评审与测试记录齐全。

## 12. 实施记录与运行配置

实现使用 `core/dispatch.py` 共用服务、`tasks` 增量关系字段和三张协调表 `dispatch_executions` / `dispatch_receipts` / `dispatch_usage`。父会话由任务的 `source_session_key` 解析，根执行从协调表关联，不重复存储规划中的全部派生字段。回执唯一键为任务＋运行版本＋父执行；用量唯一键为执行＋轮次，兼容旧单轮次主键迁移并保留旧账。自动轮次沿用原协调执行，真人新输入产生新执行并废弃旧领取。

| 配置 | 默认值 | 作用 |
|---|---|---|
| `VOCOCO_TASK_DISPATCH_V2` | 关闭 | 值为 `1` / `true` 时启用两个新入口和协调续跑；关闭停止领取待续跑，保留结果与账本 |
| `VOCOCO_TASK_RESUME_LIMIT` | 5 | 每次协调执行的自动续跑次数上限，最小 1 |
| `VOCOCO_TASK_CHAIN_TOKEN_BUDGET` | chat 用 `CHAT_TASK_TOKEN_BUDGET`，其他用 `TASK_TOKEN_BUDGET` | 根任务链累计 token 上限；0 不设链上限，不取消原每日预算 |

继续复用现有并发、每日后台预算、单次执行预算；等待父任务释放并发位，自动续跑占位。同链最多五任务、两层，换独立入口不能绕过。代码评审 profile 即使关闭新开关后人工续聊仍只读。实时语音通过原协议适配为独立会话，不尝试恢复音频父模型。
