# P2 — 体验进阶(可选项菜单,按收益逐项做)

> 前置阅读:[00-overview.md](00-overview.md) + P0/P1 文档。
> 本期不是一口气全做:下面每个子项**互相独立、可单独实现/单独放弃**,
> 建议按编号顺序(收益/成本比从高到低)。全部改动仍限定在 `claude_hermes/voice/` 包内
> (接触点预算不新增)。

## 总目标

把 P0 的"对讲机手感"升级到接近 ChatGPT 语音:更快、更自然的声音、能开口打断、
AI 干活时不冷场、任务完成能主动插话。

---

## 2-A 思考音效与固定话术(半天,先做)

**问题**:Claude 思考 1-3 秒 + 派任务确认,期间死寂。
**方案**:
- 前端:进入"思考"状态时循环播放极轻的音效(打字声/柔和白噪,音量 ≤15%),
  首句音频到达即停;音效文件放 `voice/static/`;
- 固定话术:`voice_dispatch_task` 被调用的瞬间(SSE 收到工具启动事件),前端**不等
  LLM 说完**,直接播放预合成的话术音频(「好,我去办」,首次启动时用 edge-tts 生成
  并缓存到 `data/voice/cache/`);LLM 随后的正式回复照常播。
**验收**:派任务场景从"松手到听到第一声"≤1 秒。

## 2-B CosyVoice2 音色升级(半天)

**问题**:edge-tts 音色机械、且是非官方接口有失效风险。
**方案**:`tts.py` 加 SiliconFlow CosyVoice2 后端(`FunAudioLLM/CosyVoice2-0.5B`,
流式,首包 ~150ms;API key 复用现有 `SILICONFLOW_API_KEY`),
`VOICE_TTS_BACKEND=edge|cosyvoice`,失败自动降级 edge-tts。
**成本**:约 ¥0.05/千字符(个人日常 ≈ ¥0.5/天)。
**验收**:切换后中文自然度肉耳可感,首句延迟不高于 edge-tts。

## 2-C 流式识别:边说边出字(1-2 天)

**问题**:P0 要松手才开始转写,长句等待感明显。
**方案**:
- 后端:`voice/asr_stream.py` 内嵌 sherpa-onnx + 流式 Paraformer 中文模型
  (纯本地 CPU,尾延迟 ~600ms;模型文件放 `data/voice/models/`,首次启动下载);
- 传输:新增 `WS /voice/stream`,前端 AudioWorklet 采 16k PCM 推流;
- 按住期间实时上屏灰色草稿字,松手用**现有 SenseVoice 整段转写做终稿**
  (流式模型精度略低,终稿校正一次),再进对话轮;
- 新依赖 `sherpa-onnx` 写入 pyproject,包体较大,允许做成可选 extra
  (`uv sync --extra voice`),缺依赖时自动回退 P0 行为。
**验收**:说话时 ≤1 秒延迟看到草稿字;松手到终稿 ≤0.8 秒。

## 2-D 开口即打断(全双工第一步,2-3 天,依赖 2-C 的 WS 通道)

**问题**:AI 说话时只能点按钮打断。
**方案**:
- 前端:`@ricky0123/vad-web`(浏览器端 silero VAD,AudioWorklet 运行;
  js 文件下载后本地随 voice/static/ 分发,不引 CDN);
  AI 播放期间 VAD 常开,检测到人声 ≥300ms → 触发打断;
- 打断协议:前端立刻停播+清队列 → WS 发 `{"type":"interrupt"}` → 后端取消
  本轮 TTS 合成与 stream_turn(复用 P0 stop 通道);
- **词级上下文对齐**(关键,容易漏):打断时前端上报"已播完到第几句",
  后端把该轮落库的 assistant 文本**截断到用户实际听到的句子**,并追加标记
  「(此处被用户打断)」——否则 Claude 会以为自己说完了整段;
- **假打断恢复**:打断后 1.5 秒内没有产生有效转写(咳嗽/环境音)→ 前端从断句处
  恢复播放,后端撤销截断;
- 回声防护:`getUserMedia({audio:{echoCancellation:true}})`,并在扬声器播放时
  提高 VAD 阈值。
**验收**:AI 说话时开口,≤0.5 秒内它闭嘴并开始听;咳嗽一声不会误停。

## 2-E 主动插话档 INTERRUPT(半天,依赖 2-D)

**方案**:P1 播报设置 `VOICE_ANNOUNCE` 增加 `interrupt` 档:任务终态时若正在播放,
直接打断插播「插一句——任务完成了…」;若用户正在录音则仍退回 WHEN_IDLE。
默认值保持 `idle`,该档仅手动开启。
**验收**:开启后任务完成 3 秒内听到播报;用户录音永远不被打断。

## 2-F 审批卡片(1 天,与语音无关也有价值)

**问题**:后台任务碰到 escalate 级操作(装包/git push/rm -rf)时无人审批,只能失败。
**方案**:
- executor 捕获现有危险分级 hook 的审批请求事件(先读懂 `tools/danger.py` 与
  PreToolUse hook 的现有交互形态,voice 侧只做**消费者**,不改 danger.py);
- 任务卡片上出现「⚠️ 等待批准:pip install xxx [批准] [拒绝]」;
- 同时发 web_push(复用现有 `PUSH_ON_APPROVAL` 场景),点通知进 /voice 批;
- 超时(10 分钟)未批 → 自动拒绝,任务继续或失败由现有机制决定。
**验收**:后台任务装包 → 手机收到推送 → 点批准 → 任务继续跑完。
**注**:若调研发现现有 hook 形态无法在不改核心代码的前提下转发审批,
本子项**放弃并记录原因**,不许为它突破接触点预算。

## 优先级与放弃线

| 子项 | 建议 | 理由 |
|---|---|---|
| 2-A 音效+话术 | 必做 | 半天工作量,体验提升最大 |
| 2-B CosyVoice2 | 必做 | 摆脱 edge-tts 失效风险 |
| 2-C 流式识别 | 看 2-A/B 之后的体感 | 半双工下收益中等 |
| 2-D 打断 | 想要"电话感"再做 | 复杂度最高,坑最多 |
| 2-E INTERRUPT 档 | 顺手 | 依赖 2-D |
| 2-F 审批卡片 | 独立评估 | 价值高但受制于现有 hook 形态 |

## 测试要求

每个子项独立测试文件 `tests/test_voice_p2_<子项>.py`;2-D 必须覆盖:
打断截断对齐、假打断恢复、录音期间禁止 INTERRUPT。
