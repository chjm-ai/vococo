## 已明确的产品边界

- 全局侧栏只新增「作品库」一个入口；状态、Agent、媒介类型、搜索、排序等操作都在右侧内容区。
- Library 不是文件浏览器，而是持续保留和复用产出的作品索引。
- 网站发布、生成图片、发送图片应从工具执行源头集成，不能主要依赖模型事后记得登记，也不能靠抓聊天中的 URL。
- 现有 Demo 的卡片与详情布局沿用；自动收录、历史回填、引用到真实对话需要正式实现。

## 二、建议架构：统一登记，小范围接入

```text
生成图片 ──落盘成功──────┐
发送图片 ──保存成功──────┤
发布网站 ──取得发布回执───┼─→ Library 统一登记 → 索引 + 受控原件 → 右侧作品库
显式收藏 ──验证来源──────┘           ↑
历史补录 ──预览清单→确认导入─────────┘
```

首版不做全盘文件监控、不做新事件总线、不改造全部聊天媒体存储。

### 1. 统一登记服务与原件保留

建议新增 `vococo/memory/library.py`，数据库仍使用现有 SQLite 体系；迁移与测试先在隔离副本完成，不手工改生产库。

最小持久结构：

- `library_items`：作品ID、类型、标题、归属Agent、稳定source_key、受控文件storage_key或站点URL、hash、置顶/隐藏、创建/更新/导入时间、必要元信息。
- `library_sources`：作品ID、来源动作、会话/轮次/工具调用、发布回执或生成参数、幂等事件键。一个作品可以来自多个会话或被多次发送。
- 首版文件采用 Library 独立的受控目录，按内容摘要保留一份原件；不引入通用文件引用计数和垃圾回收系统。
- 收录失败保留明确的待重试回执，报告「产出成功、收录待重试」，不要重新生成图片或重新部署，也不能静默吞掉错误。
- 稳定的登记重试键与作品身份分开，重试只补记账、不重复产出。

### 2. 生成图片接入

在 generate_image 文件成功写入后、自动展示之前调用登记服务。

- 记录 prompt、model、尺寸、当前 Agent 和会话。
- 将作品ID传给自动发送流程；聊天显示与作品收录是两件事，不因收录再发送一次图片。
- 非 Web/后台生成同样登记，不能只挂在 WebAdapter 上。
- 相同文件字节只保存一份；不同生成事件的来源参数仍分开保留。
- 原有同轮禁止二次 send_image 的逻辑继续保留。

### 3. 发送图片接入

send_image 的已有文件保存成功后调用同一登记服务，并关联当前会话。

- 与已收录内容相同：复用作品，只增加发送来源；不生成重复卡片，不更改原来的置顶/隐藏。
- 新的图片文件：自动收录为「发送的图片」，不能冒称 AI 生成。
- 建议增加可选 `purpose=output|reference|debug`，默认 output 对应用户“发送图片即收录”；调试截图/参考材料可显式选择不进作品库。
- 用户上传的图片是输入附件，默认不自动算作品，提供「收藏到作品库」。
- 外部脚本或第三方工具生成文件，不经过 generate_image 的，需经 send_image 或显式登记才能收录；不宣称能无条件覆盖所有工具。

### 4. 网站发布接入

新增受控 `publish_website` 工具，把现有发布执行和登记放进同一次工具调用，不要求模型连续执行“发布”和“登记”两个独立步骤。

- 优先包装**当前已在使用**的 `/opt/deploy/deploy.sh`，不为 Library 切换网站部署系统。
- 另接本地 `/pub` 发布和带 JSON 回执的 website-publisher 适配器；目标配置区分两套域名/根目录。
- 发布目标、应用名、来源目录由结构化参数传入；目标和可执行脚本白名单，不接受任意远程命令字符串。
- 发布成功回执提供真实 URL、应用/站点ID、版本标记；宿主工具补标题、Agent、精确来源上下文。
- 部署激活和公网验证分别记录。公网暂时超时显示「已部署，访问待验证」，不把成功部署抹掉。
- 同一站点按「稳定目标ID + app/slug」更新同一张卡片，**Agent 不参与身份键**；跨 Agent 更新不能新建站点卡片或覆盖人工归属。
- 置顶、隐藏、自定义标题不会被发布更新重置。网站最近更新时间更新，来源里保留每次发布记录。
- 显式登记已有 URL 是补充入口；任意 SSH/手写脚本/外部控制台绕过统一工具，无法保证实时自动收录。
- 本地 `/pub` 的 HTTP 访问处理函数不做登记，它既不能代表发布完成，也不知道发布者。
- 不把默认健康检查变成任意内网URL抓取：手填链接可保存，服务端验活/截图需独立地址校验与受控执行。

### 5. UI、查看与调用

- 原有全局侧栏只加一个入口，页面显示独立 Library 数据而非扫描目录。
- 支持类型/Agent/状态/搜索、置顶、隐藏恢复、详情、下载/打开网站、来源会话。
- 「引用到对话」传稳定作品ID：图片在服务端验证权限后解析为真实附件；网站带正式URL。不能只向模型发一个不可访问的标题或本地绝对路径。
- 库内搜索与取作品工具供 Agent 在后续会话中主动调用，返回最少必要元信息，按需取原件。
- 归属 Agent 只是分类，不是访问权限。Library 列表与文件接口沿用登录鉴权；**收录图片绝不等于公开发布图片**。
- 隐藏只是移出日常列表；不删除原文件，也不撤下已经公开的网站。
- 默认删除聊天不删除已收录作品；来源会话不存在时显示「来源已删除」，作品仍可用。
- 视频可沿用 send_video 同类接入；通用文档先显式收藏，文件写入不自动算产出。

## 三、历史回填：先清单，后导入

1. 从正式支持的导出/备份路径取得一致性只读历史快照；不直接修改生产数据库。
2. 图片优先从历史附件与指定媒体工具事件还原会话/Agent，再以文件hash合并 gen_* 和 ai_*；只在受控媒体目录寻找未引用原件。
3. 网站从本地发布入口和已确认的两套远端发布目录建立候选清单，再结合有完成回执的历史发布事件；不抓整段聊天中的所有URL。
4. 清单分别展示：可确认作品、重复内容、失效文件/链接、待归属项、明确不收录的输入/调试素材。
5. 有可靠来源才填 Agent/生成参数/原始时间；无证据的显示「待归属」「历史导入」，文件mtime不得伪装发布时间。
6. 旧链接迁移到新域名作为同作品别名或人工合并；不能按标题相同自动合并。
7. 用户确认导入范围后执行幂等回填；可重跑、不重复、保留导入批次以便撤销。原历史文件与会话不动。

## 四、分阶段执行与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| A | Library 索引/受控原件 + 生成/发送图片 | 生图一次一张卡；重发不重复；非Web也收录；删聊天不丢原件；调试图可排除；失败不触发再次生图 |
| B | 现有网站发布器包装 + 发布skill接入 | 发布后自动出现；重发同站更新；pin/hidden保持；超时可补记账不重复部署；两套目标不混淆 |
| C | 正式页面 + Agent 检索/引用 | 左侧单入口、右侧筛选；图片真实引用；网站可打开；来源可追溯；鉴权有效 |
| D | 历史预览清单与确认导入 | 已知重复配对成功、缺字段如实为空、重跑不重复；不把上传图/WAV/站点子文件当独立作品 |

每阶段测试与只读评审后再合并；正式后端合并后另询问是否重启。A、C 已完成；B 完成 local/Kimmy 静态接入，其他目标与后端应用待做；D 仅完成只读预览，确认导入待后续实现。

## 待确认的默认规则

建议按以下默认值落地，不增加首版配置页：

1. 生成图与发送的成果图自动收录；调试/参考图可显式排除，用户上传图默认不收。
2. 同站更新一张卡；同内容图片重复发送只加来源，不改作品归属。
3. 收录即独立保留原件，删聊天不删作品；隐藏不删除，也不改变公开链接。
4. 历史先列候选清单，确认后再导入；来源未知不猜归属。
