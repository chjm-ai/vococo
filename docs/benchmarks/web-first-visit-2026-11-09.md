# Web 弱网首访按需加载验收（2026-11-09）

## 结论与边界

- **高把握**：工作台、设置、作品库不再首访下载；冷首访压缩正文减少约 17%，JS 从 17 个降到 15 个。
- **中把握**：最终交错手机样本中，模拟 4G 冷首访中位数 3.92 → 3.49 秒（约 11%）；样本少、主机负载有波动，不能外推公网耗时。
- **未证明暖缓存有稳定收益**：最终 4G 暖缓存约慢 0.09 秒，弱网暖缓存约快 0.20 秒；探索轮曾出现弱网暖缓存明显变慢，保留原始结果，不挑样本。
- 指定基线 `5f3accd` 在本地模拟弱网冷访问中 3/3 未进入默认界面；新版 3/3 成功。旧版没有有效中位数，不用失败样本计算提速倍数。
- 未部署、未合并 main、未重启生产、未推送 GitHub；**没有验证真实公网** `vc.qingmood.com`。

## 实现范围

1. `lazy.js` 用普通同源 `<script src>` 加载原始 JS，保留原全局作用域和原 CSP，不使用字符串包装、eval 或 blob 执行。
   - 同模块共享下载 Promise；连续点击只初始化一次，只有最新入口意图执行。
   - 下载失败明确提示，再点可重试；部分初始化失败提示刷新，不盲目重跑已执行过的脚本。
   - 切换到其他会话/视图后，旧入口下载完成不能抢回页面。
2. 原设置文件里的推送/SW 底座移到常驻 `app-core.js`；会话菜单、滑动操作、查找、删除/重命名等移到常驻 `sidebar.js`。设置面板 UI 留作按需模块。
3. HTML 的非执行 JSON 配置保存模块 URL，沿用后端现有内容哈希注入；`lazy.js` 接入真实静态路由、版本列表和 SW 白名单。不清空已有缓存桶。
4. `/conversations` 仍与脚本下载并行；响应到达后等 `DOMContentLoaded`，再调用跨脚本入口，避免 `connectTaskStreamOnce` 等尚未定义。默认依旧进入统一文本/语音视图，没有先展示普通会话再切换的替代路径。
5. **未拆语音核心、未改长会话后端、未改鉴权流程、未延迟 `/commands`**。斜杠菜单继续使用原有预加载，避免首次输入的菜单等待与额外状态管理。

## 测试口径

- 同一 WebAdapter 实例、同一临时空数据库，使用真实后端路由；只切换静态资源。无模型调用，不读写生产会话数据。
- 基线静态资源：通过 `git archive 5f3accd` 导出到全新临时目录；没有复用中断前的混合导出目录，也不必递归删除已有测试材料。
- 改后：在 `217572f` 分支基线上实现本次改动；该基线已有的定时任务“稍后处理”功能不属于本次性能优化。
- Chromium 模拟 iPhone：390×844、DPR 3、iPhone iOS 18 UA、触屏、4 倍 CPU 限速。不是 iOS Safari 真机测试。
- 4G：1600 kbps / 120 ms；弱网：400 kbps / 300 ms。每个网络/缓存组合，新旧版本各 3 次，相邻交错采样。
- 冷访问：新浏览器上下文、保留测试口令、禁 HTTP 缓存、绕过 SW。
- 暖缓存：每次独立上下文先访问一次，再在同一上下文导航测量；允许 HTTP 缓存，仍绕过 SW。SW 的升级/离线路径单独测试。
- 进入主界面：DOM 已解析完成，默认 `callView` 可见且 `S.surface === 'call'`。不是登录页消失、不是骨架屏可见。脚本全部就绪后再等 10 秒仍未进入记失败。
- `bytes` 是 ResourceTiming 的压缩正文大小，包含命中缓存的资源体积；`networkBytes` 是 transferSize（含浏览器估算头部）。**暖缓存的 bytes 不代表网络重传**。

### 弱网旧版失败诊断

- 原样测量：脚本全加载后仍停在 `surface: chat`，默认 `callView` 隐藏。
- 另做诊断轮，使用临时 `217572f` 基线（其 `app-core.js` 与 `5f3accd` 无差异），仅在 `tryEnter` catch 内插入日志、不暂停调试器，连续 3 次输出：`BASELINE_TRYENTER connectTaskStreamOnce is not defined`。
- 该异常原本被 catch 消化，随后 SSE 又把服务状态置回 online，不能只凭“在线”字样判定首屏可用。
- 诊断轮有插桩，不纳入时间比较；最终表格使用未经插桩的基线。

## 首次入口成本

以下来自独立补充验收轮，不与前述 24 个性能样本混为同一轮。每种网络每个入口测 1 次，同时连点 6 下；不是三次中位数。入口可见耗时含下载、解析、主机调度；工作台还等数据完成首次渲染。下载耗时是新增的按需等待部分，不把整个入口耗时都算作新增成本。

| 入口 | 4G：下载 / 可见 / 数据确认 | 弱网：下载 / 可见 / 数据确认 |
|---|---:|---:|
| 设置 | 0.381 / 1.072 / 1.993 s | 0.665 / 1.808 / 3.980 s |
| 作品库 | 0.354 / 0.898 / 1.255 s | 0.528 / 1.106 / 1.697 s |
| 工作台 | 0.418 / 1.157 / 1.353 s | 1.280 / 2.377 / 2.463 s |

设置数据确认包含 `/settings` 返回并切到外观页验证三个真实控件；默认统计页另有历史日志扫描，不把该扫描完成作为模块下载成功的门槛。作品库确认临时空库请求完成并显示空态，工作台确认工具栏已渲染。数据确认时间包含测试操作和浏览器通信开销，不是纯接口耗时。

## 功能与异常路径

| 路径 | 结果 |
|---|---|
| 首屏没有请求三个按需模块 | 通过，检查 ResourceTiming，不只看 HTML |
| 三入口首次打开，连续点击 6 次 | 每模块仅一次版本化下载，无重复初始化 |
| 三模块下载失败，再次点击 | 每次失败批次只提示一次，恢复网络后可重试 |
| 脚本部分初始化时抛错 | 明确提示刷新；再点不会再次执行或重复绑定 |
| 直接打开 `/workbench/window`，再刷新 | 工作台正常出现，独立窗口类保留 |
| 未打开设置时使用会话菜单、输入 `/` | 菜单可用，未被按需设置阻塞 |
| 下载期间切回统一对话入口 | 下载完成不抢回工作台 |
| 真实旧版 SW + 旧缓存 → 新版 | HTML 和模块 URL 更新，新模块正常执行 |
| 新模块未缓存时离线首次打开 | 明确失败，联网后再点成功 |
| 模块缓存后离线刷新、再次打开三个入口 | 模块可执行；动态数据仍显示原有离线/失败态，不声称离线可获取新数据 |
| 网络恢复后刷新，再打开设置 | 通过 |
| 页面运行异常 | 正常路径未发现未捕获异常；故意注入的初始化异常单独断言 |
