# 可编辑 PowerPoint

本技能独立实现，使用 MIT 许可的 PptxGenJS，不依赖或复制其他公司的 PPT 技能。

## 交付规则

- 默认交付 `.pptx`，文字、表格、图表必须使用原生对象。图片内部不可逐元素编辑；矢量图也不等于数据图表。
- 不把整页截图塞进 PPTX，不用 HTML/PDF 替代用户要的可编辑 PowerPoint。
- 用户上传已有 PPT 要求套模板/保持原样时，明确首期不支持直接修改；询问是否按新稿重建，不能装作已无损编辑。
- 这不是浏览器内 PPT 编辑器；用户下载到 PowerPoint/WPS 编辑，或在聊天要求修改源 JSON 后重生成。
- 所有文件写当前会话工作目录或已配置的正式 output_dir；不能写技能源码目录、其他会话或公开发布目录。

## 工作流

1. 有必要时确认受众、目标、页数和风格；信息齐全则直接做。长稿先给大纲，用户确认后生成。
2. 在成果目录新建内容 JSON，参考 [格式与限制](references/format.md) 及 [六页示例](examples/six-slides.json)。
   字数超限时精简或拆页，不擅自缩小成难读的小字，不伪造数字/来源。
3. 用技能自己的脚本生成，路径中的 `技能目录` 是当前 SKILL.md 所在位置，不是当前工作目录：

   ```sh
   node "技能目录/scripts/generate.cjs" "/成果目录/内容.json" "/成果目录/演示-v1.pptx"
   python3 "技能目录/scripts/check.py" "/成果目录/演示-v1.pptx"
   ```

   生成脚本拒绝覆盖已有文件。后续修改 JSON 时保留旧版本，输出新文件名。
   缺依赖时明确报告，请维护者运行 `python3 "技能目录/scripts/setup.py"`；
   不能静默装包，也不在业务沙箱内绕过审批安装。生成过程本身不联网，不使用额外 AI API。
4. 若已安装 LibreOffice 和 Poppler，渲染实际 PPT 并 Read 逐页图片，修正断行、遮挡等问题：

   ```sh
   python3 "技能目录/scripts/check.py" "/成果目录/演示-v1.pptx" --render "/成果目录/预览-v1"
   ```

   结构检查/对象边界检查不等于视觉验收。没装渲染器必须说明“未验证实际 Office 排版”，
   不生成另一个网页当作实际 PPT 渲染结果。即使渲染通过，仍不能声称已在 PowerPoint/WPS 人工打开编辑过。
5. Web 渠道用 `mcp__vococo__send_file(path=绝对PPTX路径,title=演示稿标题)` 交付下载卡片。
   可再交付内容 JSON 或渲染后的 PDF；只报本机路径不是 Web 交付。
   send_file 未加载时说明“服务需更新/重启以启用文件下载”，不要用公开网站发布绕过私有下载。
   CLI/TUI 不支持卡片时给本机文件位置，不虚构下载链接。
6. 回复只保留：文件、页数、可编辑范围、尚未完成的验收。测试数据须明确标注示例。

## 首期能力

- 16:9；封面、条目、双栏、表格、柱形/折线/饼图、图文页。
- 自定义字体及背景/正文/强调色；原生文本、形状、表格、图表及内嵌 XLSX。
- 本地 PNG/JPEG（相对 JSON 所在目录，不接受远程 URL、隐藏路径或软链）。
- 单稿 1–50 页。脚本对字数、表格行列、数据和输出覆盖有硬检查。
- 不支持自由 HTML/CSS 转换、动画、任意模板导入、已有 PPT 无损修改、在线多人协作。
