# AI 原生 PowerPoint 工作台

核心是让 AI 操作 PPT，不是选择模板填 JSON。通过现有 Read/Write/Bash 工具执行原生 API；不需要额外模型服务或在线编辑器。

## 选择操作方式

- 新建和修改默认使用 **python-pptx** 完整 API，自主构图：文字及富文本、形状/连线、图片及裁切、分组、表格、图表数据、位置尺寸、字体颜色、图层、页面和备注。
- 新建时也可直接使用 **PptxGenJS** 完整 API。两者的操作与可运行示例见 [原生操作](references/native-api.md)。不要为了统一接口再造受限 canvas JSON。
- `scripts/pptx_workspace.py` 提供检查、稳定ID定位、图层/页面操作、拒覆盖另存；其余能力直接调用库，不被辅助函数列表限制。
- `generate.cjs` 和 [旧 JSON 格式](references/format.md) **只用于旧稿兼容**，不是默认流程，不把其六种版式/字数限制当 PPT 能力边界。

## 编辑与验收闭环

1. 信息足够就执行；长稿先确认大纲。参考稿应实际读取内容和对象，不能只凭标题猜样式。
2. 已有稿先检查对象：用 vococo 安装环境的 Python 执行 `scripts/pptx_workspace.py 稿件.pptx`，按需用 `--slide-id ID` 减少输出。
   先 Read [原生操作](references/native-api.md) 确认解释器和脚本路径。业务文件在工作区外时，获授权后只读复制进当前工作区；原件保持不动。
3. 在当前工作区编写脚本。用检查结果的 `slide_id/shape_id` 定位，不依赖重排后会变化的页码/数组位置。新建任意构图，或直接修改既有对象，不必重建整稿。
4. 用 `save_new(deck, 新版本.pptx)` 另存，保留原件及编辑脚本。不要直接覆盖用户原稿。局部文字优先改 run，直接赋值整框 `.text` 会清掉原富文本。
5. 渲染**实际输出的 PPTX**：

   ```sh
   "$PY" "技能目录/scripts/check.py" "/成果目录/演示-v1.pptx" --render "/成果目录/预览-v1"
   ```

   `$PY` 是安装了 python-pptx 的解释器；渲染需本机 LibreOffice + Poppler（pdftoppm/pdfinfo）。不联网、不自动装包。
   输入须在当前工作区；正式 output_dir 在外部时，在该获准目录作为 cwd 执行渲染，不放宽沙箱。
6. 用 Read 查看实际逐页 PNG，检查断行、遮挡、层级、图片裁切和内容遗漏。长稿先看实际 PNG 拼接的总览，再读重点页原图。
   发现问题 → 修改原生对象 → 新版本另存 → 重新渲染。不能停在“已渲染”，也不能拿 HTML/Pillow 另画的版面冒充 PPT 预览。
7. Web 使用 `mcp__vococo__send_file` 交付最终 PPTX，可附实际 PDF。只报本机路径不是交付；下载回执不等于浏览器已保存。
   CLI/TUI 给本机位置。回复保留文件、页数和未验收边界；不要擅自公开发布。

## 必须保留的边界

- 正文/表格/数据图表用原生对象；图片内部不可逐元素编辑。不能用整页截图或 SVG 冒充完整可编辑文稿。
- 主题/模板是可选素材，不能把复杂参考稿强塞成六种版式。文字密度由实际内容和渲染决定，不用固定字数上限替代判断。
- 图表数据须有来源，示例数据明确标记。客户真实界面只用原素材裁切/脱敏，不交生图模型重画；素材不提交源码、不擅自外发。
- 库不保证任意动画、SmartArt、第三方扩展和嵌入对象无损。先在副本验证，遇到不支持对象保留并说明，不能声称任意 PPT 都可无损编辑。
- 渲染器是 LibreOffice，不是 PowerPoint。结构通过、渲染成功、逐页视觉复核、PowerPoint/WPS 人工编辑是四种不同验收；分别如实说清。
- 所有脚本/成果写当前工作区或获准 output_dir，不写技能源码目录，不绕过已有权限。辅助函数不是新沙箱；Bash/文件工具继续受宿主权限保护。
- 缺渲染器明确说明“未验证实际 Office 排版”；缺依赖由维护者审批安装，不在业务任务静默装包。源代码安装可用 `uv sync` 安装项目锁定的 python-pptx，PptxGenJS 另用 `scripts/setup.py`。
