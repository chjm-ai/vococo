# PPT Master 接入与交付适配

设计与制作默认交给共享安装的 **PPT Master**，不要再自行发明设计工作流或模板生成器。本技能只负责宿主边界、最终文件验收与交付。

## 默认入口

1. 先读 [PPT Master 接入](references/ppt-master.md)，解析共享技能的绝对目录，确认完整安装及可用解释器。
2. 当前工具清单提供 `ppt-master` 时调用该技能；未列出时，用 Read 加载该绝对目录的 `SKILL.md`，按上游入口执行完整性检查与路由。不要调用不存在的技能名，也不要只运行转换器而跳过设计流程。
3. 新建、重设计、既有稿编辑分别按上游路由执行；模板是可选输入，不是能力边界。确认关口必须等待用户，不能把“开始做”一律解释成跳过策略的 Quick 模式。
4. 上游负责设计与输出，以下宿主约束始终有效：客户材料不擅自外发、不自动装包、不启动后台常驻服务、原稿不覆盖、最终 PPTX 真实渲染后私有交付。
5. 缺失或校验失败就明确报告，停止该路线。不能悄悄退回自建固定版式；仅在用户明确选择直接 API 操作或旧稿兼容时，才使用下面的补充能力。

## 原生 API 补充（非默认设计流程）

- **python-pptx / PptxGenJS** 完整 API 与示例见 [原生操作](references/native-api.md)，用于用户明确要求的局部修复或上游缺口，不另造受限 canvas JSON。
- `scripts/pptx_workspace.py` 提供检查、稳定ID定位、图层/页面操作、拒覆盖另存。
- `generate.cjs` 和 [旧 JSON 格式](references/format.md) **只用于旧稿兼容**，不是默认流程。

## 编辑与验收闭环

1. 默认遵循上游设计、确认和制作流程。参考稿应实际读取内容和对象，不能只凭标题猜样式；下面的 API 检查与编辑仅适用于明确选择补充操作的情况，不替代上游流程。
2. 补充检查可用 vococo 安装环境的 Python 执行 `scripts/pptx_workspace.py 稿件.pptx`，按需用 `--slide-id ID` 减少输出。
   先 Read [原生操作](references/native-api.md) 确认解释器和脚本路径。业务文件在工作区外时，获授权后只读复制进当前工作区；原件保持不动。
3. 补充 API 编辑脚本写当前工作区，用检查结果的 `slide_id/shape_id` 定位，不依赖重排后会变化的页码/数组位置。上游项目则修改其源 SVG/原生往返工作区，重新走上游检查与导出，避免两份源稿分叉。
4. 所有路线均使用新的输出路径，保留原件和上个版本；不覆盖用户原稿。API 路线用 `save_new(deck, 新版本.pptx)` 另存；局部文字优先改 run，整框 `.text` 会清掉原富文本。
5. 渲染**实际输出的 PPTX**：

   ```sh
   "$PY" "技能目录/scripts/check.py" "/成果目录/演示-v1.pptx" --render "/成果目录/预览-v1"
   ```

   `$PY` 是安装了 python-pptx 的解释器；渲染需本机 LibreOffice + Poppler（pdftoppm/pdfinfo）。不联网、不自动装包。
   输入须在当前工作区；正式 output_dir 在外部时，在该获准目录作为 cwd 执行渲染，不放宽沙箱。
6. 用 Read 查看实际逐页 PNG，检查断行、遮挡、层级、图片裁切和内容遗漏。长稿先看实际 PNG 拼接的总览，再读重点页原图。
   发现问题 → 修改原生对象 → 新版本另存 → 重新渲染。不能停在“已渲染”，也不能拿 HTML/Pillow 另画的版面冒充 PPT 预览。
7. Web 使用 `mcp__vococo__send_file` 交付最终 PPTX，可附实际 PDF。只报本机路径不是交付；下载回执不等于浏览器已保存。
   CLI/TUI 给本机位置。回复保留文件、页数和未验收边界；不要擅自公开发布。

## 必须保留的边界

- 正文/表格/数据图表用原生对象；图片内部不可逐元素编辑。不能用整页截图或 SVG 冒充完整可编辑文稿。
- 主题/模板是可选素材，不能把复杂参考稿强塞成六种版式。文字密度由实际内容和渲染决定，不用固定字数上限替代判断。
- 图表数据须有来源，示例数据明确标记。客户真实界面只用原素材裁切/脱敏，不交生图模型重画；素材不提交源码、不擅自外发。
- 库不保证任意动画、SmartArt、第三方扩展和嵌入对象无损。先在副本验证，遇到不支持对象保留并说明，不能声称任意 PPT 都可无损编辑。
- 渲染器是 LibreOffice，不是 PowerPoint。结构通过、渲染成功、逐页视觉复核、PowerPoint/WPS 人工编辑是四种不同验收；分别如实说清。
- 所有脚本/成果写当前工作区或获准 output_dir，不写技能源码目录，不绕过已有权限。辅助函数不是新沙箱；Bash/文件工具继续受宿主权限保护。
- 缺渲染器明确说明“未验证实际 Office 排版”；缺依赖由维护者审批安装，不在业务任务静默装包。源代码安装可用 `uv sync` 安装项目锁定的 python-pptx，PptxGenJS 另用 `scripts/setup.py`。
