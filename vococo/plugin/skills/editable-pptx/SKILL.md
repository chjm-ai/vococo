# PPT Master 接入与交付适配

设计与制作默认交给共享安装的 **PPT Master**，不自建设计工作流、模板生成器或原生编辑工作台。本技能只负责宿主边界、最终文件验收与交付。

## 入口与宿主边界

1. 先读 [PPT Master 接入](references/ppt-master.md)，按其中“解释器与校验”解析 `$PY` 和适配技能的绝对目录，运行 `scripts/ppt_master_check.py`。
2. 校验成功后，当前工具清单提供 `ppt-master` 时调用该技能；未列出时，用 Read 加载校验输出的绝对 `SKILL.md` 路径。按上游入口执行完整性检查与路由，不调用不存在的技能名，不只运行转换器而跳过设计流程。
3. 新建、重设计、既有稿编辑均按上游路由执行。确认关口必须等待用户，不能把“开始做”一律解释成跳过策略的 Quick 模式。
4. 缺失或校验失败就明确报告并停止，不修补、不绕过、不切换自建生成器。
5. 客户材料不擅自外发、不自动装包、不启动后台常驻服务。所有脚本与成果写当前工作区或获准 output_dir，不写技能源码目录，不绕过已有权限。
6. 原稿在工作区外时，获授权后只读复制进工作区。编辑沿用上游源稿和往返流程，每次导出指定尚不存在的新版本路径，保留原稿及上个版本。

## 最终文件验收与交付

1. 上游完成设计、质量检查与原生 PPTX 导出后，渲染**实际输出的 PPTX**：

   ```sh
   "$PY" "适配技能绝对目录/scripts/check.py" "/成果目录/演示-v1.pptx" --render "/成果目录/预览-v1"
   ```

   预览目录必须是新目录。输入须在当前工作区；正式 output_dir 在外部时，在该获准目录作为 cwd 执行，不放宽沙箱。
   渲染需本机 LibreOffice + Poppler（pdftoppm/pdfinfo），不联网、不自动装包。渲染器禁宏、只打开原稿副本，但不是独立系统沙箱。
2. 检查结构报告及实际 PDF/PNG 页数，再用 Read 查看逐页 PNG，核对断行、遮挡、层级、图片裁切和内容遗漏。长稿可先看实际 PNG 拼接的总览，再读重点页原图。
3. 发现问题 → 修复上游源稿 → 新版本导出 → 重新检查和渲染。不能停在“已渲染”，不能拿 HTML/Pillow 另画版面或源 SVG 截图冒充 PPT 预览。
4. Web 使用 `mcp__vococo__send_file` 私有交付最终 PPTX，可附实际 PDF；只报本机路径不是交付，下载回执不等于浏览器已保存。CLI/TUI 给本机位置，不擅自公开发布。
5. 回复保留文件、页数、实际看过哪些页及未验收边界。缺渲染器明确说明“未验证实际 Office 排版”；缺依赖交维护者审批安装，不在业务任务静默安装。

## 能力与验收边界

- 正文/表格/数据图表用原生对象；数据级图表/表格按上游 native-data 契约导出。图片内部不可逐元素编辑，不能用整页截图或 SVG 冒充完整可编辑文稿。
- 模板是可选输入，不是能力边界；文字密度以内容和实际渲染为准，不以固定版式、字数上限替代判断。
- 图表数据须有来源，示例数据明确标记。客户真实界面只用原素材裁切/脱敏，不交生图模型重画，不提交源码、不擅自外发。
- 任意动画、SmartArt、第三方扩展及嵌入对象不保证无损。先在副本验证，不能宣称任意 PPT 都可无损编辑。
- 结构检查、LibreOffice 渲染、AI 逐页视觉复核、PowerPoint/WPS 人工编辑是四种不同验收，必须分别如实报告；渲染成功不等于视觉自动通过或 Office 全面兼容。
